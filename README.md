# Consultation Scheduler ASP

Веб-приложение для автоматизированного размещения консультаций преподавателей в уже существующей сетке университетского расписания.

Проект разработан в рамках выпускной квалификационной работы. Основная идея системы — не пересоставлять всё расписание заново, а аккуратно встроить консультации в готовую сетку с учётом занятости преподавателя, учебных групп, ограничений и личных предпочтений.

## Основные возможности

- создание заявок на проведение консультаций;
- выбор учебных групп, количества консультаций и типа недели;
- задание ограничений и предпочтений преподавателя;
- учёт базового расписания преподавателя и групп;
- учёт вручную заданной занятости преподавателя;
- пакетная обработка нескольких заявок одного преподавателя;
- генерация нескольких допустимых вариантов размещения;
- оценка вариантов по мягким ограничениям;
- просмотр результата в виде сетки расписания;
- выбор итогового варианта для дальнейшего согласования.

## Особенность подхода

Система использует Answer Set Programming для описания ограничений задачи.

В отличие от простого поиска свободного слота, приложение формирует общий вариант размещения сразу для набора заявок преподавателя. Это позволяет учитывать конфликты между заявками, занятость преподавателя, расписание учебных групп и предпочтения пользователя в рамках одного запуска генерации.

## Как работает генерация

1. Преподаватель создаёт одну или несколько заявок на консультации.
2. Система получает данные о группах, расписании и занятости.
3. Backend формирует набор допустимых кандидатных слотов.
4. На основе этих данных создаются ASP-факты.
5. Решатель clingo строит допустимые варианты размещения.
6. Варианты оцениваются по мягким ограничениям.
7. Лучшие варианты сохраняются и отображаются пользователю.

## Жёсткие ограничения

При генерации система исключает варианты, в которых:

- консультация пересекается с занятостью преподавателя;
- консультация пересекается с занятиями учебных групп;
- нарушается тип недели;
- консультация попадает на исключённый день;
- несколько заявок одного преподавателя конфликтуют между собой;
- консультация попадает на день ВУЦ для соответствующей группы.

## Мягкие ограничения

Для выбора более удобного варианта используются мягкие ограничения:

- предпочтительный день проведения консультации;
- нежелательность первой пары;
- нежелательность последней пары;
- компактность размещения относительно существующего расписания.

Варианты сравниваются по вектору оценки: сначала учитываются нарушения предпочтительного дня, затем нарушения по первой и последней паре, после этого — суммарный штраф за компактность расписания.
